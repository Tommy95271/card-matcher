Phase 1 第一階段：需求起源與前端原型 (MVP)

1.1 背景痛點

2026 年台灣主流權益切換型信用卡（國泰世華 CUBE 卡、台新 Richart 卡、玉山 UBear、兆豐宇宙明星 BT21）權益規則多變，一般民眾在結帳當下很難快速判斷哪張卡回饋最高、當天是否需要切換方案。

1.2 技術選型與建置

  • 前端核心：原生現代 JavaScript (ES Modules) + Vanilla CSS + Vite 建置工具。
  • 資料庫：抽離結構化店家通路與方案規則庫（cards-data.js）。
  • 核心演算法：輸入店家關鍵字（如「博客來」、「全聯」、「UberEats」），系統自動進行權益方案比對，並即時提醒今日方案鎖定狀態。
  • 初期託管：使用 GitHub Pages（tommy95271.github.io/card-matcher）快速驗證。

Phase 2 第二階段：點數對帳與 Notion 資料庫整合 (Mode 3)

2.1 點數查核與客服申訴話術生成

針對「銀行常漏發點數、使用者容易忘記消費當日切換方案」的問題，擴充了記帳與點數查核模組：

  • 試算引擎：記錄消費金額、適用方案與預期回饋點數（小樹點、台新Point、現金回饋折抵）。
  • 狀態追蹤：🟡 待核對 ➔ 🟢 已入帳 ➔ 🔴 漏給需申訴。
  • 客服話術產出：一鍵比對官方權益公告與短少點數，自動生成專業客服申訴文案。

2.2 突破 CORS 限制：Universal Notion GAS Relay

因前端直接請求 Notion API 會遭遇瀏覽器跨網域安全限制 (CORS)，且一般使用者不便自建 Node 伺服器：

  • 開發 Google Apps Script Serverless 中繼站（gas-backend/Code.gs）。
  • 智慧網址解析：使用者只需在網頁貼上 Notion 資料庫完整網址，系統自動解析 32 位元 Database ID。
  • 提供完整的記帳、修改核對狀態、刪除（封存）與雙向拉取功能。

    GAS -- 官方 REST API (無 CORS 限制) --> Notion["📝 Notion Database (私人筆記庫)"]

Phase 3 第三階段：Firebase 雲端即時同步 (Mode 2)

3.1 零設定跨裝置 Live Sync

為了照顧無 Notion 帳號的大眾用戶，引入 Firebase 生態系：

  • Google 一鍵登入：免註冊帳密，直接使用 Google 帳號登入。
  • 即時雙向推播：透過 Firestore onSnapshot 即時監聽，實現手機、電腦、平板跨裝置毫秒級同步。
  • 多租戶安全防護：撰寫 firestore.rules，嚴格限制只有本人帳號可讀寫個人消費紀錄。
⚠️ 核心技術攻堅：競態條件（Race Condition）修復
在同時開啟 Firebase 與 Notion 時，Firestore 的快速同步曾覆蓋正在等待 Notion 回傳的 notionPageId。我們加入了雙向保護鎖與回寫機制，確保兩種同步模式並行時資料 100% 一致。

4.3 GitHub Actions ⇄ Google Apps Script (Clasp) 自動化部署管道

什麼是 clasp？
clasp（Command Line Apps Script Projects）是 Google 官方推出的指令列工具，專門用來解決 Google Apps Script 傳統只能在網頁編輯器手動修改、無法與 Git 結合的痛點。 
sequenceDiagram
    autonumber
    actor Dev as 👨‍💻 開發者
    participant GH as 🐙 GitHub Repository (main)
    participant GA as ⚙️ GitHub Actions (CI/CD Runner)
    participant Clasp as 🤖 Google Clasp CLI
    participant GAS as ☁️ Google Apps Script Cloud Engine
    participant Webhook as 🔗 既有 Webhook Endpoint

    Dev->>GH: git push origin main (包含 gas-backend/)
    GH->>GA: 觸發 deploy-gas.yml
    GA->>GA: 📦 安裝 @google/clasp 全域工具
    GA->>GA: 🔑 從 GitHub Secrets 注入 CLASPRC_JSON (OAuth 憑證)
    GA->>Clasp: clasp push --force (同步 Code.gs & appsscript.json)
    Clasp->>GAS: 上傳覆蓋雲端程式碼
    GA->>Clasp: clasp deploy -i  -d "CI/CD Auto Deploy"
    Clasp->>GAS: 發布新版本至現有部署作業
    GAS-->>Webhook: 維持原 Webhook URL 不變，功能立即生效！
  • 本地代碼管理與 Git 整合：所有後端邏輯（Code.gs、appsscript.json）均納入 Git 進行精確版本追蹤。
  • 自動化 OAuth 憑證注入：本機執行一次 clasp login 產生憑證後寫入 GitHub Secrets，雲端自動授權發布。
  • 無感升級 (Zero-Downtime Deployment)：指定部署 ID 讓 Webhook URL 永遠維持同一串網址，前端 localStorage 完全無需更動設定。

ADR 架構決策記錄 (Architecture Decision Records)

ADR-001：為什麼選擇 Vanilla JS + Vite 而非 React / Vue / Angular？
• 零執行時開銷（Zero Runtime Overhead）：免載入數百 KB 框架底層，手機載入時間縮短至 0.2 秒以內。
• 毫秒級熱更新（HMR）：Vite 基於原生 ES 模組，存檔即更新。
• 長期穩定無維護負擔：遵循原生 Web 標準，永無框架大版本升級斷代風險。
ADR-002：為什麼選擇 Cloud Firestore 而非舊版 Firebase Realtime Database？
• 文件/集合階層架構：天然支援多用戶隱私隔離（users/{uid}/expenses/{id}）。
• 複合查詢與排序：支援同時依日期倒序與狀態複合檢索（orderBy('date', 'desc')）。
• 台灣在地機房（asia-east1）：伺服器位於彰化，延遲極低、存取極速。
ADR-003：為什麼選擇 Google Apps Script (GAS) 作為 Notion Relay 而非 Firebase Cloud Functions？
• 100% 永久零成本且免綁信用卡：Firebase Cloud Functions 要求升級 Blaze 方案（強制綁定信用卡）才能發送外網請求呼叫 Notion API；而 GAS 完全免費且免綁卡。
• 零門檻開源複製：任何人「複製貼上 ➔ 點部署」即可使用，無需註冊 GCP 開發者專案。
ADR-004：為什麼採用雙軌同步策略（Firestore + Notion）？
• 大眾需求：Google 登入即享 0 門檻跨裝置毫秒級 Live Sync。
• 進階需求：貼上 Notion 網址即可備份至個人筆記庫。
• 防護機制：實作雙向 ID 持久化保護鎖，徹底解決異步寫入時的競態覆蓋問題。
ADR-005：為什麼將託管從 GitHub Pages 遷移至 Firebase Hosting？
• 專屬獨立根網域：擁有乾淨頂層網域（card-matcher-2026.web.app），根除 SPA 路由子路徑問題。
• 同源 Edge CDN 邊緣加速：與 Firebase Auth / Firestore 同處 Google 全球骨幹網路，快取與存取速度顯著提升。
• 全自動 CI/CD：結合 GCP 服務帳號金鑰與 GitHub Actions，達成 git push 即全自動雲端建置發布。
ADR-006：為什麼引入 Google clasp 實現 Google Apps Script 的 CI/CD 自動化？
• 程式碼即基礎設施 (Code as Single Source of Truth)：gas-backend/Code.gs 本地化管理，每一次更動皆受 Git 精確版本控管。
• 雙軌自動化發布：只要 git push origin main，前端自動發布至 Firebase Hosting，後端 GAS 自動透過 clasp push 與 clasp deploy 上傳部署。
• 固定 Webhook URL：自動升級原有部署作業，使用者 Webhook 網址永遠維持不變。
